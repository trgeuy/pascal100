# `reference/` — distilled hardware references

These `.md` files are **ours**: text-only emulation references, each written *from* a period
scan (a vendor data sheet or a MITS manual) and each citing that scan by filename in a `Source:`
line at its top. They carry what a developer reopens the scan for — register maps, port
addresses, status/control bit tables, disk geometry and timing, boot sequences, and the quirks
that bite an implementer.

The **scans themselves are not redistributed** (they are large and not ours; see
`.gitignore`). `docs/sources.md` is the manifest — what each original source is, where it came
from, and the traps paid for once. Read it before trusting any single number here; several of
these sources contradict themselves, and `sources.md` records which reading won and why.

The `Source:` links point at `#` — a placeholder to be filled in with a real URL later.

| [Intel 8080/8085 Assembly Language Programming](Intel%208080-8085%20Assembly%20Language%20Programming.md) | Intel's 8080/8085 programmer model (manual 9800301D): the A/B/C/D/E/H/L + SP/PC register set and pairs, the **S Z AC P CY** condition flags with exact semantics (AC is DAA-only and untestable; `IN` sets no flags), the **PSW flag-byte layout** (8080 filler bits 5=0/3=0/1=1 — **undefined on the 8085 ⚠**), the instruction-group taxonomy and the Appendix-A per-CPU T-state timing model (8080 480 ns–2 µs vs 8085 320 ns–2 µs clock period). | [Intel 8085 undocumented instructions and flags](Intel%208085%20undocumented%20instructions%20and%20flags.md) | What Intel left out of the 8085 manual: the two extra condition bits **V** (overflow, PSW bit 1) and **K/X5** (PSW bit 5), with the exact per-instruction rules from Ken Shirriff's **silicon die** reverse-engineering (`V = carry-in⊕carry-out of bit 7`; `K = V ⊕ sign`, except `INX`/`DCX` where K is the 16-bit carry) — authoritative; and the ten undocumented opcodes (`DSUB ARHL RDEL LDHI LDSI RSTV SHLX LHLX JK JNK`) with opcode/octal/length solid but **operation and flag effects second-hand and flagged ⚠** (`LDHI`/`LDSI` flag behavior is a documented conflict). | [Digicomp Research Pascal-100](Digicomp%20Research%20Pascal-100.md) | Dual-processor 16-bit S-100 CPU boardset (two cabled cards): a **Western Digital Pascal Microengine (WD9000)** that executes **UCSD Pascal III.0 P-code natively** + a stock **Z80** (I/O, interrupts, CP/M); only one runs at a time, the other in HOLD, switched by one byte to a **write-only System Control Port** (even, default `D0`; odd Map Output Port `D1`). Documents the port byte table (`80`/`00` processor swap; `C0`/`40`, `C1`/`41` Map enable/disable per processor; `C2`/`42`, `C3`/`43`, `C4`+`44`, `45`/`C5`), the **dynamic address-translation Memory Map** (Standard 16×8K→128K, Extended 64×2K→1M/512K, loaded Z80-only with **inverted** contents), **Microengine memory-mapped I/O** (word `FFpp`=8-bit port `pp`, `FEpp`=16-bit), the **Z80 Power-On-Jump** (`C3 00 X0`, DIP U242, J202), the interrupt model (pINT/NMI→Z80; Microengine int → semaphore SIGNAL, scratch `1F880/1`, vector `1F8C0/1`), the **byte=word×2** rule + reset init vector `1F8D0`, the boot sequence, the **ZMCOM** interprocessor area at byte `80h`, and the IEEE-696 bus behavior. **⚠ Not emulated** — reference for possible future S-100 CPU-board support. |
| [WD UCSD Pascal III.0 — the P-machine and OS tables](80-0130016-00A0_UCSD_Pascal_III.0_Operating_System_Reference_Manual_Jul82.md) | Western Digital's *UCSD Pascal III.0 Operating System Reference Manual* (80-0130016-00A0, Jul 1982), **Appendix C, Table C-3**: every III.0 P-code operator in WD's Pascal-like metalanguage, with the declarations it uses (`mscw`, `tib`, `sib`, `memtrix`, the registers). The specification of the `pascal100` P-machine core. Word-addressed, stack grows down, `NIL` = `FC00`, IEEE reals. **⚠ Printed slips are flagged inline with the reading to implement** (e.g. `LDP` missing a dereference, `WAIT` printed `+ 1`, `SPR` garbled, `CPI`/`CXI` walking the static chain from the new frame) — and **opcode `9F` is both `BNOT` and `RBP`** in WD's own tables: to be settled on the real machine. Section 3 lists the differences from the Pascal-100 manual's appendix F (`iorslt`, 128-entry segment vector, priority queues). Sections 4-5 add **Appendix H** (the OS initialization numbers that show where a boot stopped) and **Appendix I** (the III.0 **H3** OS globals: SYSCOM, unit table, disk directory, code-file segment dictionary, driver tasks and semaphores; ordinary records are allocated forward). Section 6 adds **Table C-1**, the opcode list: all 100 C-3 operators match it exactly, it adds `RBP`, and it leaves `40`–`77`, `A8`–`AF`, `E8`–`FF` unassigned. |
| [IEEE Std 696-1983: the S-100 bus standard](IEEE_696_1983.md) | ANSI/IEEE Std 696-1983, the formal S-100 standard that pascal100's **IEEE-696 bus type** follows: the 24-bit memory and 16-bit I/O address (Table 4), the status bus with **sXTRQ\*** and no sSTACK (Table 5), the **8/16-bit protocol** (sXTRQ\*/SIXTN\*, even/odd bytes, the master's byte-serial response; the standard does not fix the byte order), interrupts, RESET\*/SLAVE CLR\*/POC\*, and the full pin list (Table 6) with each pin's Altair-bus difference. |

| [SD Systems ExpandoRAM](SD%20Systems%20ExpandoRAM.md) | The original ExpandoRAM ("I"), an S-100 DRAM board (MK4115/MK4116). **⚠ It has no I/O port at all** — a static, memory-mapped board whose "banks" are four fixed groups of 8 chips strapped to 8K/16K address slices by an 8-position DIP switch (U2 → 74LS138 → RAS0–3); per-bank write-protect + PHANTOM/manual output-disable. **Not** a runtime bank switcher — do not confuse with the ExpandoRAM-II. |
| [SD Systems ExpandoRAM II](SD%20Systems%20ExpandoRAM%20II.md) | The second-generation board: 4 banks of 8 chips, 4116 (64K/board) or 4164 (256K/board, "4-64K banks"). **Port FF** latches a page from **D0–D3 only**; an 82S130 PROM (U8, 4 outputs = 4 bank enables) decodes board S (0–7, S3 D2–D0) + page P + bus A15–A14 into one bank. Fig 2-4 (clean in the deramp copy) gives both maps for 16K banks: **48K** = 8 boards, pages 0–9 of 48K + common 16K at C000 (board 0 bank 3) + a 16K page A; **32K** = 6 boards, pages 0–A of 32K + common 32K at 8000. Plus the 1980 Technical Bulletins (105/109/111/112: refresh, wait-state and clock/reset-pin rework only). ⚠ Page A's address differs between text (C000) and figure (8000); the 4164 page map and reset are not documented; three PROM part numbers. Not emulated (the `bankmem` board that modeled it was removed in 2026-11). |
| [SD Systems ExpandoRAM III](SD%20Systems%20ExpandoRAM%20III.md) | The third-generation board (1983; the /696 version is IEEE-696): 32 × 4164 in 4 banks of 64K → **256K/board**. **Port FF** latches a page number from **D0–D3 only**; a 9-input PROM (U8, COSMOS-48K) decodes board/config switches (S) + page (P) + bus A15–A14 (A) into an active-low bank enable **and the RAM's own A14–A15**, so each 64K bank holds four 16K cells from different pages. Shipped map: **10 × 48K pages on 2 boards**, CP/M/MP/M/COSMOS (common C000–FFFF) or OASIS (common 0000–3FFF) chosen by S3 switch 5; board 0–3 on S3; one M1 wait (E14–E15). ⚠ Fig 2-2 has cell labels that cannot be right (pages 4 and 8, a second page-0 cell, P=A) — unresolved without a PROM dump. Not emulated (the `bankmem` board that modeled it was removed in 2026-11). |
| [Vector Graphic 64K Dynamic RAM](Vector%20Graphic%2064K%20Dynamic%20RAM.md) | Z-80-only S-100 DRAM board: **port 40H, one-hot** bank select (`1<<bank`, `0x01`→0 … `0x80`→7), 8 banks / ≤8 boards / 512K, bank 0 force-enabled at power-on/RESET (POC clears the port-40H latch and DO0 is pre-inverted so the cleared state = `0x01`). Jumper "area D" trims the top in 8K steps (ships at 56K, not full 64K). The one banked card whose encoding `altairsim` models correctly (`vram`). |
| [North Star HRAM](North%20Star%20HRAM.md) | HORIZON DRAM board (HRAM-32/48/64): **port C0H**, and the byte is **not** a bank number — **bit 0 = on(0)/off(1) command, bits 1–7 = one-hot** address of which bank the command toggles (per-board JP1). Only **≤6 banks** usable (one of bits 5/6/7 is spent on parity); software must switch the old bank off before the new one on. Two independently-switchable 32K sections (JP2); JP1 also sets the reset state (default: always on). |
| [Cromemco 64KZ / 64KZ-II RAM](Cromemco%2064KZ%20RAM.md) | Two S-100 DRAM boards as one family: **port 40H**, and the BANK SELECT byte is an **8-bit mask of active banks** (bit N ⇒ bank N on/off, several at once — `OUT 40H,28H` = banks 3 **and** 5), 8 banks. Each board is two 32K blocks A/B with per-block bank-membership switches (SW2/SW3) + a RESET-enable switch; 64KZ ≤512K with DMA/OVERRIDE, 64KZ-II ≤448K with per-16K-half enables and no documented DMA. |
